WHAT CHANGES

Same answer.
Different data movement.

The copy counter counts logical event deliveries to reader workers, not bytes or measured heap. Loading 100,000 events into two native readers sends 200,000 event copies. Shared mode sends memory handles and root descriptors, not cloned event records.

Queries return small result pages in both paths. Those replies, local decoded strings, wrappers, caches, and allocations still have a cost. Zero event copies does not mean zero allocation or zero messages.

Native code gets a fair implementation.

The default native path sends only incremental deltas. The full-copy option is a separate, clearly labelled baseline. Both use the same search and summary functions. Both can freeze this append-only stream: native arrays retain a prefix length, while zerocopy retains immutable roots.

Live timings are observations, not a speed claim.

The paths run concurrently and can compete for CPU. Timings separate publication/attachment and queries. Dataset construction and owner-side append work are not in those numbers. Startup and rendering are excluded. Results are checked after timing.
