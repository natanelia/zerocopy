WHAT CHANGES

Same answer.
Different data movement.

The copy counter counts logical event deliveries to reader workers, not bytes or measured heap. Loading 100,000 events into two readers sends 200,000 event copies per replica path. Shared mode sends memory handles and root descriptors, not cloned event records.

Queries return small result pages in all paths. Those replies, local decoded strings, wrappers, caches, and allocations still have a cost. Zero event copies does not mean zero allocation or zero messages.

Each library gets a fair implementation.

All three paths use the same five primitive columns and search functions. Immutable.js uses real Lists and batched withMutations appends. Queries read Lists directly, with no toJS() conversion. The default sends only incremental deltas to both replica paths; full replication is an optional baseline.

Immutable.js shares structure between versions within each worker. It does not share that JavaScript heap across workers. Publication includes plain-column encoding, structured clone, and List reconstruction in each reader. Freeze retains actual Immutable.js and zerocopy roots. Native arrays retain a prefix length for this append-only workload.

Live timings are observations, not a speed claim.

The paths run concurrently and can compete for CPU. Timings separate publication/attachment and queries. Dataset construction and owner-side append work are not in those numbers. Startup and rendering are excluded. Results are checked after timing.
