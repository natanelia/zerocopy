Method, environment & source data

Checking the source build metadata…

Median of seven measured samples after two warm-ups. Eleven read cases and seven original catalog cases rotate through fresh owner and two-reader workers. Every warm-up and measured sample is retained: 99 read samples and 63 catalog samples. These are timings, not memory measurements.

Full objects, selected fields and the first answer

Full-object .get(): complete, deeply frozen records. The cold query is the first access in a fresh reader; the cached query immediately repeats the same 1,000 IDs before any validation pass. All implementations receive the same 910 hits and 90 misses.

Selective query: find available books and return ID, name, price and revision. Native Map, Immutable.js, Immer, ZeroCopy .get() and ZeroCopy getView() return the same ordered projection. Selective queries do not compute a full-record fingerprint.

Construction through first answer: construction + initial publication + first full-object worker round-trip, added within each sample before the median. It includes both reader acknowledgements and full-result transport. Worker startup, module loading, input generation, reference checks and DOM paint are excluded. Worker startup is reported separately.

Local read bars show the slower of two parallel reader durations; both individual durations remain in the export. The separate worker round-trip includes scheduling and complete response transport. After first and repeat queries finish, an independent reference checks every result value, count, miss and position. Current revision 1 and retained revision 0 are checked after replacing 100 records.

Explicit getView().toObject() returns fresh mutable native values; getView().toObject({ freeze: true }) returns fresh deeply frozen values. These are separate materialization workloads, not standard .get() or its decoded-object cache.

The original catalog control

Legacy query timers include full-field fingerprints and worker reply transport; only the independent reference comparison is untimed. Full-copy bars appear only for publishing an edit and replacing + publishing 100 products, directly below SharedMap. Other legacy operations use the four baseline cases. Initial replica publication copies the complete catalog; incremental edits copy only 100 changed records.

Source identity and interrupted runs

Page setup reads build metadata without loading the library. Run rechecks the source commit and verifies fetched library, workload and dependency hashes before workers start. Fetched hashes do not attest already evaluated browser modules. Raw JSON includes build/browser identity, APIs, freeze contracts, timing boundaries, all samples and correctness checks.

Stopping or failing a run keeps the previous completed charts. The interrupted attempt can be downloaded separately with its partial samples and failure details; incomplete medians never replace a complete result.
