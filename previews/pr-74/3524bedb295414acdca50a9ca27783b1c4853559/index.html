01 / THE MENTAL MODEL

More workers.
Less baggage.

Your dataset shouldn’t need a new home every time you start a worker.

With structured cloning, each reader gets its own copy. ZeroCopy puts collections in shared storage and gives each reader an immutable view.

Change a product, publish a revision, and readers can move forward when they’re ready. A captured snapshot stays exactly as it was.

A SHARED CONNECTIONTS
main.ts · one writer
if (!crossOriginIsolated) {
  throw new Error('Enable COOP/COEP headers first.');
}
const { SharedMap } = await import('zerocopy');
const { createState } = await import('zerocopy/state');

const state = createState({
  stock: new SharedMap('number').set('item/42', 12),
}, { copy: false });

const worker = new Worker(
  new URL('./worker.ts', import.meta.url),
  { type: 'module' },
);
window.addEventListener('pagehide', () => {
  state.dispose();
  worker.terminate();
}, { once: true });

await state.connect(worker);
state.update('stock', stock => stock.set('item/42', 7));
worker.ts · local reads
import type { SharedMap } from 'zerocopy';
import { connectSharedSession } from 'zerocopy/worker';

type Model = { stock: SharedMap<'number'> };
const shared = await connectSharedSession<Model>();
const initial = shared.current;

shared.subscribe(snapshot => {
  // Both reads are local. Neither asks the writer.
  console.log(snapshot.stock.get('item/42')); // 7
  console.log(initial.stock.get('item/42'));  // 12
});

// When this session is no longer needed:
// shared.dispose();

05 / CHOOSE IT FOR THE RIGHT REASONS

A powerful fit.
With clear boundaries.

Sharing can remove repeated dataset copies. It doesn’t make every operation faster, and it doesn’t mean zero allocations.

Should I use ZeroCopy? →
+

Large data. Multiple readers.

Useful when several threads need stable views of the same changing dataset.

Catalogs Editors Data tables Graphs Filtering Simulations
↳

Plan for ownership and lifetime.

One writer per arena. Browser isolation. Asynchronous snapshot delivery. Explicit compaction for long-lived data.

Read the memory guide →
−

Small, single-threaded data?

Native collections are often the simpler choice. Measure your application before adding a shared-memory layer.
