Spatial viewport queries

Query shared bounding boxes in workers, apply sparse feature edits, and install rebuilt indexes while the editor keeps changing.

Source documentationView source ↗
On this page
  1. Edit and rebuild
  2. Dedicated worker transport

Import the optional zerocopy/spatial entry point to search 2D bounding boxes from an owner or a dedicated worker. A packed Flatbush index and its feature ID table live in shared buffers. Sparse edits live in a separate immutable ZeroCopy map. This lets workers finish queries against the original tile while the editor moves or deletes features.

ts
import { applySpatialEdits, buildSpatialIndex, querySpatialIndex } from 'zerocopy/spatial';

const base = buildSpatialIndex([
  { id: 12, bounds: [0, 0, 3, 3] },
  { id: 41, bounds: [10, 0, 12, 3] },
], 0);
const edits = applySpatialEdits(undefined, 1, [
  { id: 12, bounds: null },
  { id: 41, bounds: [2, 0, 12, 3] },
]);

querySpatialIndex(base, [0, 0, 3, 3]);        // [12]
querySpatialIndex(base, [0, 0, 3, 3], edits); // [41]

Use stable unsigned 32-bit feature handles. Applications with string IDs can keep the handle on a TanStack metadata row. Handles must stay unique for the lifetime of a retained tile history. The result lists matching handles in ascending order. Bounds use [minX, minY, maxX, maxY] in one planar coordinate system. Edges are inclusive. Indexed boxes require finite coordinates. Query boxes allow infinite extents. Run an exact geometry predicate on the candidates when an application needs line or polygon intersection.

Edit and rebuild#

  • buildSpatialIndex(features, revision = 0) creates a base for a complete tile revision. Every feature has a unique numeric id and a bounding box.
  • applySpatialEdits(previous, revision, edits) returns a new change map. Pass undefined for the first batch. Assign a strictly increasing safe integer revision to each committed batch, starting above the base revision. A box replaces a feature's previous bounds. A null box deletes it. Replaying the same latest batch preserves the existing handle. A conflicting or older write to an already edited ID throws. Initializing a nonempty change map and applying later edits require an allocating owner.
  • querySpatialIndex(base, box, changes?) searches the packed index and scans recent changes. An updated feature suppresses its old index hit even when its new bounds are outside the viewport. Changes at or before the base revision have already been incorporated and are skipped.
  • rebuildSpatialIndex(base, changes, revision) creates a replacement index directly from packed bounds and the captured change map. A reader can build it using just those two inputs and the revision of their publication. It accepts a revision at or after the base and rejects changes newer than that revision. Capture the overlay when scheduling the job, since later edits may overwrite an earlier change for the same ID. If the overlay has no newer entries, the result reuses the base's buffers.
  • pruneSpatialEdits(changes, baseRevision) removes entries incorporated by a replacement index. If a worker builds a base from revision 10 while the owner advances to 12, install that base with the current change map pruned through 10. Keep revisions, base and changes from the same tile history. Capture the replacement pair together before sending it to a reader. Pruning reduces future query work. The arena lifetime rules determine when old backing memory can be reclaimed.
ts
// In a reader, after attaching the change map for this publication.
import { rebuildSpatialIndex } from 'zerocopy/spatial';

const rebuilt = rebuildSpatialIndex(base, capturedChanges, capturedRevision);
postMessage(rebuilt);

On the owner, install a returned base only if its tile is still active and its revision is at least as recent as the installed base. Pair it with the latest overlay pruned through the returned revision. An older job can finish last.

A query scans every unpruned change. Choose a rebuild threshold from measured edit density and viewport latency. The browser replay includes deletes, retained readers, an index rebuilt while edits continue, and binary deck.gl paths. Rebuilding from packed bounds took a median 2.6 ms in that four-reader replay, compared with 22.3 ms for decoding the shared metadata rows. See the trial results and measurement conditions.

Dedicated worker transport#

Send the base once per generation using ordinary structured clone, without a transfer list. Treat the shared buffers as immutable in every realm. Send the change map, metadata and geometry together with the normal ZeroCopy transport.

ts
// Owner, with the worker and application data already available.
worker.postMessage({
  base,
  revision: 1,
  roots: getWorkerData({ edits, rows, geometry }, { copy: false }),
});

A reader uses await initWorker(message.roots) to obtain the matching collections, then calls querySpatialIndex(message.base, viewport, edits) with the attached edit map. Use a revision and a viewport request ID to discard stale asynchronous results. A worker only needs a new base when the index is rebuilt. Follow the browser isolation setup for shared-memory transport.
