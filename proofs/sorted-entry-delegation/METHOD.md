## Frozen fixtures and nine endpoints

Before construction call public `configureMemory({maximumBytes:16777216})`. Create six independent arenas by calling public `resetSortedMap()` before each map. Retain only the final immutable snapshot of each construction and a frozen fixture registry; never mutate, grow, reset or attach anything during the measurement batches. Each arena's configured maximum is 16 MiB, six maxima total 96 MiB; this bounds arena growth, not process memory or actual physical commitment. Failure to construct within the fixed limit blocks the study rather than changing the limit.

For size N, use keys `k` plus the four-digit zero-padded decimal index i, for `0 <= i < N`; values are `3*i+1`. Insert in descending i order with the public constructor and repeated `set`. Expected natural order is ascending i, independently generated without traversing the library. Numeric means value type `'number'`; all keys are strings. Construct P first. Other independent maps, in this order, have 32, 1, 0, 256 object, and 256 custom-comparator entries. Freeze ordinary expected records/arrays before use.

## Clock boundary, consumption and validation

An operation includes the public method call, iterator creation/acquisition, every advancement and yielded item, and terminal exhaustion. Use ordinary `for...of` over a newly obtained iterator; do not pre-create it, time only `next`, stop early, or materialize an output array. Empty N0 must still create and drain its iterator to completion. F4097 includes the entire public `forEach` call with one fixed callback prepared during setup; reset its scalar consumer state inside each operation. No per-operation callback allocation is required.

Use the same small, fixed consumer in both arms. At the start of each operation set item count q to zero and unsigned checksum h to 2166136261. For each item update `h = Math.imul(h ^ token,16777619) >>> 0` and increment q. For numeric entries and F4097, token is the numeric value plus `key.charCodeAt(4)`; O256 substitutes `value.score`; K4097 uses that key code unit alone; V4097 uses the numeric value alone. Thus every yielded item is consumed, with explicit key/value work. The checksum is a corruption screen, not exact proof of string contents or ordering.

The batch clock surrounds only the repeated whole-operation loop, including per-operation state reset, traversal and checksum accumulation. Add each operation's q to a safe-integer batch item count and h to a modulo-2^32 batch checksum; compare both against independently calculated expected values after stopping the clock. Keep scalar results, never an output history. The estimand includes identical loop, function-call and checksum cost; do not subtract an empty-loop estimate. Report time per complete operation, not per entry; N0 has no per-entry denominator.

Outside every clock, validate each fixture and public operation against independently generated expected sequences: exact count, every key, every numeric value or complete object shape/content, exact order, final exhaustion, snapshot size/freeze and deep-frozen decoded objects. For `forEach`, validate every callback key/value and its order. Validate once before warmed batches and after every batch using a separate complete untimed traversal. Release temporary validation state promptly. This validation warms caches uniformly and is part of the fixed workload sequence, but not its measured latency. Post-batch checks do not claim that a checksum proves every timed item exactly.

## Analysis and fixed decision

For each engine/row/block compute `d = log(C/B)` from the process means. Across the six blocks report geometric ratio `exp(mean(d))` and two-sided paired 95% Student-t interval `exp(mean(d) ± 2.570582*sd(d)/sqrt(6))`. Batches are not independent replicates. No resampling, bootstrap, pooling engines, choosing a favorable baseline, or substituting an A/B average. These small-n intervals assume approximately independent, reasonably behaved block log-ratios; balancing and diagnostics do not establish that on a shared host.

Report the same intervals for `log(A/B)` and separately `log(later baseline / earlier baseline)`, with chronological observations. Major systematic A/A bias means an entire interval above 1.05 or below 0.95. Major P or V4097 bias blocks a hosted gain verdict; bias in other controls makes them unresolved. An interval merely crossing 1 or one noisy point is not itself a regression. Keep all diagnostics, including large inconclusive scatter.

A meaningful primary lead requires P's ratio **<=0.95 and 95% upper bound <=0.95 in both engines**, with complete source/correctness/calibration/quality admission and no blocking A/A bias. For **all eight controls**, a 95% lower bound **>1.02** in either engine parks the candidate, even if other quality diagnostics are unresolved. A control whose upper bound exceeds 1.02 without its lower bound exceeding 1.02 is unresolved, not passed; unresolved calibration, quality or A/A also remains explicit. Do not add samples to resolve uncertainty. Cold/startup observations remain unresolved descriptive diagnostics: apparent material adverse results require review before promotion. The joint primary rule is a conjunction; unadjusted control intervals are warning screens, not simultaneous no-regression certification.

Report absolute ns/complete operation, all six process means and paired ratios, intervals, calibration, quality, A/A, first-drain/startup observations and limitations for every endpoint.
