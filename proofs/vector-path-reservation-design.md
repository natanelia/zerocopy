# Vector path reservation: correctness candidate

This local candidate retains bit-identical vector-tree storage reuse and reduces
a changed write to one allocator request. Successful changed writes restore
main's parent-first addresses and byte layout. It is a correctness/mechanism
candidate, not a demonstrated performance improvement or a proven fix for the
historical changed-write regressions. No candidate latency timing, publication,
pull request, or broader workload matrix was performed or prepared.

The comparison baseline is `3773c6e519c7c0958da13727ed1082f449f3ee25` (main).
The local historical vector-only parent is
`d01bed9f12d4b846f0afe30679f55f577877f196`; its published counterpart is
`1bf473e03803b1ca15e8e87d0100f3c62055fdcb`.

## Mechanism and successful-write contract

Only `vecSetAt` and its exported `vecSet` wrapper differ among 69 production,
build, package and configuration files checked against main. `tailSet`, public
wrappers, encoding, all other core functions, and optional numeric/geometry
kernels remain exact main. No ABI export, import, wire format, cache, SIMD flag,
or short-copy routine changes.

The descent reads the selected pointer once at every existing ancestor. At the
leaf, stored u64 bits are compared with the incoming f64 representation. Equal
bits return the existing leaf and propagate unchanged pointers upward without
allocation, padding, or copying. Missing nodes are materialized even when the
new value is zero. Signed zero and NaN payload distinctions are preserved at
the WASM boundary; host JavaScript Number canonicalization is unchanged.

After detecting a change, the leaf reserves `256 + depth * 128` bytes once. It
occupies the last 256 bytes; each returning parent uses `child - 128`. For a
valid append-only cursor H and depth D, root is `align8(H)`, leaf is
`align8(H) + 128D`, and final cursor is `align8(H) + 128D + 256`. This equals
main's successive parent-first allocations, including four-byte cursor
alignment. Existing siblings and old published bytes remain unchanged.

For an existing changed depth-D path, logical allocator calls fall from D+1 to
one. Selected-pointer loads remain D, and copy calls remain D+1, covering
`256 + 128D` bytes. The candidate and historical no-op design each add one
leaf-value load, an equality comparison, and ancestor equality checks compared
with main. Copies still execute leaf-first, unlike main's parent-first copies.
These are source-level operation counts, not physical loads, instruction
counts, cache measurements, or a latency result. The depth-zero case still has
one allocator request in all variants.

Public valid setters still encode first and return a fresh frozen handle. Tree
no-ops share descriptors, so existing compaction/checkpoint identity coalescing
and shared-state publication suppression persist. Tail no-ops keep main's
allocation and publication behavior. Uninterned strings, objects and nested
snapshots can allocate encoding records before the core is reached.

## Depth, arithmetic and failure boundaries

The source comment's public-depth statement applies to ordinary vectors
generated by `push`/`pushMany`: `checkedSize` caps size at `0x3fffffff`, and
`vectorDepth` therefore generates at most depth five. It is not a validation
rule for every public handle. The constructor and `fromWorkerData` accept a
caller-supplied depth unchanged.

The new raw guard rejects unsigned depths above 16,776,702, ensuring the path
size cannot wrap and does not exceed `0x7fff0000`. The allocator separately
checks the absolute heap end and available memory. This is not a depth-five
guard or a guarantee that every arithmetically allowed recursion depth can
execute; engine stack limits still apply. Raw shifts retain WASM's modulo-32
behavior. Tests cover raw depths 6, 8 and 32 and selected index-zero forwarding
through both public construction routes at those depths.

Arbitrary deeper descriptors are not ordinary generated vectors. A retained
probe demonstrates the same pre-existing behavior on main and candidate:
at handmade depths eight and 32, setting index 31 writes raw value 19, but
reading index zero first can make the public leaf cache return zero at index
31. Wrapped ancestor shifts use low index bits while the public cache groups
32 values. The supplemental test consequently asserts selected-path forwarding
and main-equivalent bytes, not general list validity for arbitrary descriptors.
No unrelated descriptor validation or getter change is included.

Failed reservations intentionally have different side effects. On a valid path,
the candidate's failed single allocation commits no path bytes, heap cursor, or
partial backing growth. Main/historical code can complete earlier allocations
and copies before a later allocation fails. Across the 25 exhausted-capacity
scenarios per variant, main consumes 0–640 bytes and changes 0–12 unpublished
bytes; historical vector-only consumes 0–768 bytes and changes 0–83 bytes;
candidate consumes/changes zero. All old published bytes survive.

The separate raw depth-600 example starts with 128 bytes free in two pages and
allows at most three pages. Main and historical code consume 65,664 bytes and
grow to 196,608 backing bytes before trapping. The candidate consumes zero and
stays at 131,072 backing bytes. These are measured allocator/failure states,
not equivalence claims. Public encoding may already have appended records
before a reservation fails. Malformed pointers, manually rewound heap cursors,
concurrent mutation and stack-exhaustion thresholds are outside the successful
valid-path proof; this is not a general transactional setter guarantee.

bytes were unchanged during this validation. Its six separately compiled
baseline/historical/candidate and instrumented builds were hash-checked.
WASM, portable modules and declarations were also rebuilt freshly from the
candidate. Compiler is AssemblyScript 0.28.20, bundler Bun 1.4.2, local Node
v24.19.0. Local Node is not the historical CI Node 22 runtime.

## Validation scope and qualifications

- Raw proof: 3,312 layout cases, 63 mechanism traces, 78 failure cases and three
  arithmetic guard cases. Includes aligned/four-byte cursors, growth, all used
  bytes, snapshots, pointer addresses, signed zeros and quiet/signaling NaNs.
- Public portable proof, per Node/Bun and checkout/packed run: five typed cases,
  all 16 historical workload fixtures and 75 allocation/identity invariants.
- Supplemental boundaries, per Node/Bun run: 102 partially missing-path layout
  comparisons and six caller-depth selected-path cases. Earlier unsupported
  arbitrary-index assumptions and their failed logs remain in the evidence.
- Actual shared and copy workers pass under both Node and Bun, including old
  snapshots, changed writes, forks, read-only rejection and writer growth.
- Fresh builds, all eight type configurations (including both typed-values
  optional-property modes), and the installed-package check pass.
- Seven focused files: Node passes 223/223. Bun's grouped run passes 222/223;
  typed JSON list reconstruction/compaction exceeds the unchanged five-second
  test timeout once. That single case passes in isolation at the same timeout
  (one executed, 30 skipped). The grouped failure is retained and is not
  relabeled a full Bun pass. No timeout or source behavior was relaxed.
- Initial unsupported `--minWorkers` invocations and an unmatched isolated
  name pattern are retained as test-runner setup errors, not test passes.
- Independent static reviews check valid-path correctness, arithmetic and
  failure scope, logical instrumentation, and actual artifact/source binding.

This is focused local validation, not a full-suite or browser pass. The
historical source guard deliberately remains pinned to the older candidate and
does not accept this reservation variant; it was not weakened or represented
as a current-candidate pass. A later timing gate would need a newly reviewed
candidate pin before it can run.

## Historical adverse evidence and a later decision

Both earlier artifacts and their raw observations remain unchanged:

- [Original b857 run](https://github.com/natanelia/zerocopy/actions/runs/37833317184):
  9/20 changed controls were inconclusive. The tiny changed-number tail was
  slower in all four quartets on Node (+2.74%, individual 95% CI +0.31% to
  +5.23%) and Bun (+1.14%, +0.03% to +2.27%). Its ZIP SHA256 remains
  `ca93cc510e3f14864706aea95ea305daefdf08e396d3c6884ae133342739cd8a`.
- [Vector-only 1bf run](https://github.com/natanelia/zerocopy/actions/runs/37837826481):
  11/20 changed controls were inconclusive. Node changed interned strings at
  depth two were +2.74% (+0.43% to +5.11%); Bun changed numbers at depth three
  were +2.74% (+1.46% to +4.03%). Both were slower in all four quartets. Its
  ZIP SHA256 remains
  `3aa354607222fc3535a160ae73a2074fb86c907fd3160d0402b193d79e7a5ee9`.

Neither prior result establishes performance acceptance, and no favorable
interval is inherited by this candidate. All 16 historical workload shapes,
ordering, samples, floors, caps and statistical code remain byte-for-byte
frozen: ten changed controls, two unchanged tail controls and four tree targets;
matched A/A, balanced four-quartet ABBA/BAAB, quartet log ratios with t(df=3)
intervals, unchanged 2% loss margin, no A/A subtraction, no dropped samples and
no compensating no-op gains for ordinary-write losses. A broader matrix is not
prepared. The next decision is whether this reviewed mechanism merits a
separately authorized exact-source performance gate.

## Reproduction

Use the pinned dependencies and Bun 1.4.2. Build the root WASM and portable
package before invoking the proofs. The first command regenerates raw evidence;
the following commands consume its immutable compiled oracles:

```sh
node scripts/build-wasm.mjs
bun scripts/build-browser.ts
bun run build:types
node proofs/vector-path-reservation.mjs /tmp/vector-reservation-proof
node proofs/vector-path-reservation-public.mjs /tmp/vector-reservation-proof
bun proofs/vector-path-reservation-public.mjs /tmp/vector-reservation-proof
node proofs/vector-path-reservation-boundaries.mjs /tmp/vector-reservation-proof
bun proofs/vector-path-reservation-boundaries.mjs /tmp/vector-reservation-proof
node proofs/noop-sequence-worker.mjs dist/shared.js vector-only
bun proofs/noop-sequence-worker.mjs dist/shared.js vector-only
```

An optional second argument to the public proof selects an extracted package
directory for exact-tarball verification. The proof never invokes the historical
performance driver. The review manifest preserves command receipts, individual
logs, raw JSON, source/package hashes, initial failures and independent reviews.
