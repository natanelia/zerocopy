# Single-lookup object-read correctness screen

This experiment adds one four-line early return in `Arena.value`, before `let slot`. For object and nested values (codes 0 and 4), it calls the existing `find` or `radixFind` once and passes the leaf to the existing decoder. This removes redundant outer `ReadCache.slot` probes, including changed roots, cold keys and misses. It does not mean only one internal `Map.get` occurs on a cold read.

This is a correctness-only screen. It contains no latency measurement or speed claim. It does not establish performance on any engine or processor.

The runtime candidate is `042b41a7f68a89a10751f285eef79259adfe4aa3`, tree `1ed648927dc122450b7c979409f605c260c389e4`, with direct parent main `3773c6e519c7c0958da13727ed1082f449f3ee25`. It changes only `arena.ts` and `cached-object-read.test.ts`. The proof commit must be its direct child and add exactly these four proof/workflow files. The source guard reconstructs the exact generic early return from baseline and rejects the older exact-root-only branch. It hashes every tracked file at baseline, runtime candidate and proof pins.

Both source pins run the same 21-case candidate test file. Baseline expects three `ReadCache.slot` probes and the candidate expects one. The probe is scoped to a test and restored in `finally`. These counts are mechanism evidence, not a latency estimate. The full suite must report all 774 assertions passed, including the 21-case overlay; skipped, missing, pending or failed cases fail the gate. The original tests, configuration, worker concurrency and five-second test timeout remain unchanged. Only default and JSON reporters are selected on the full-suite command.

Coverage includes all three map kinds, slot zero, missing leaves, stale and alternating roots, deletion and reinsertion, Unicode aliases, long keys, hash collisions, object/entry/character cache limits, nested descriptors, growth, compaction, and read-only shared/copy attachments. The unchanged dedicated worker proof tests both transports for all three map kinds in real Node workers, including nested lists. Existing built task lifecycle, Node worker and typed JSON worker checks, declarations, public type checks and installed-package checks remain required.

The baseline worktree receives the exact candidate test file before checks. This is its only source addition. Production baseline bytes stay unchanged. Each role runs independently, so a baseline failure cannot hide whether the candidate was attempted. After WASM and browser builds succeed, all remaining checks are attempted even if the full suite or a type check fails; any failure still fails the job.

Each command has a GNU `timeout` process-group bound and a ten-second forced-kill grace period. The suite has a 300-second outer cap; builds and types have 120–240 seconds, existing worker checks 60–90 seconds, the six serial dedicated workers 210 seconds, installation and package checks 180 seconds. Each log retains command, start/end timestamps and separate command/log exit codes in `commands.tsv`. An exit code of 124 (or 137 after forced termination) is a supervision timeout, never a pass. These outer limits do not modify test-level timeouts. The 45-minute job limit is only a final safety ceiling.

The workflow runs only on the first non-forced push to `proof/object-read-correctness-20261009` immediately after the pinned runtime commit. Publication must first create that branch at the runtime pin and then push the proof child. It retains complete or partial logs, JSON test output when produced, both full source archives, exact tested overlay, runtime and proof hash manifests, versions, generated lockfile, compiler hash, root WASM hashes, and built `dist` in a portable tar.gz with SHA-256 checksums. It does not merge or deploy.

No dependency lockfile is tracked at these pins. The workflow uses normal `bun install`, retains the generated lockfile and uses a task-local npm cache. Separate jobs may resolve different transitive dependencies; compare their lockfiles and compiler/build receipts before accepting paired results.

Prior local checks passed the 21 focused candidate and baseline-overlay cases, builds, declarations, public types, package and Node worker checks. The local full suite recorded five original five-second test timeouts and reached a 300-second process cap; no cause or full-suite pass is claimed. This CI screen must establish the exact paired full-suite and worker results before timing. A passing result is not performance clearance: the earlier adverse Node alternating-root measurement remains unresolved until this exact refinement receives the separate controlled performance study.
