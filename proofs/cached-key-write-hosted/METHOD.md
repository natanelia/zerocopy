## Five endpoints

1. **Sole primary:** `SharedMap('object').setMany` replacing 32 already admitted keys, `k000` through `k031`. Alternate prebuilt batches of `{id: i, revision: 0}` and `{id: i, revision: 1}`, beginning with a changed revision. Retain the original snapshot and the current result. Report time per complete 32-key batch, including serialization, UTF-8, native allocation/insertion, wrappers, and natural GC. Grouping 32 revisions describes a finite edit burst; many consecutive bursts amplify that operation without introducing a reset. This is a sustained small-record session, not an end-to-end UI latency claim.
2. **Nested secondary:** the same keys and replacement pattern in a nested `SharedMap`, alternating two prebuilt child snapshots in one dependency Arena: a numeric map containing `v: 0`, and its public `set('v', 1)` successor. Encoded descriptors must be at most 256 bytes; reject a larger fixture before timing. Child construction is outside timing. This includes dependency bookkeeping and descriptor serialization, not child updates.
3. **Persistent miss control:** first admit keys `s0000` through `s2047`, each with `{seed: 1}`, through public writes in a separate map sharing the same Arena, then seed and replace the 32 unadmitted keys above. Their initial leaf lookup always misses even when the collection already contains them. Cache seeding and its retained snapshot are outside timing.
4. **Primitive control:** identical 32-key numeric `setMany` replacements. This bypasses `Arena.leaf` and measures an unchanged bulk path with the same public operation.
5. **Fresh-key control:** one fresh-Arena 5,000-key object import, matching the existing documented `map-json-setMany` workload shape. Every leaf lookup initially misses. It gets fresh-process paired observations, not a reused warmed cache. Its single import cannot obtain a throughput clearance below the 500 ms observation floor; keep it descriptive/unresolved in that event. Four adverse block ratios above 1.02 block advancement, as in the accepted one-shot startup-control precedent. It cannot qualify the primary.

No extra engine/path matrix: pinned Node portable and Bun source entries only. Byte-limit saturation, aliases, reentry, oversized scalar writes, and worker transport remain correctness coverage, without timing claims.

## Source allocation bound and complete child accounting

Static FNV arithmetic for the 32 fixed keys finds distinct low-eight-bit hashes and at most three keys per first nibble. There are no full-hash collision buckets. A batch uses the merged PR30 pointer scratch at 16384, adding no heap pointer array. `mapLeaf` takes at most 44 bytes for each primary record: 16-byte header, four key bytes, at most 22 JSON bytes, rounded to four. That is 1,408 bytes per batch. `mapBatch` allocates a root branch of at most 72 bytes; each of 32 replacements below it needs at most one additional branch/overlay, bounded conservatively by 72 bytes. All roots originate from these public batches, with no journal. Thus at most 2,376 index bytes and 3,784 total bytes fit a **4 KiB/batch bound**. Initial construction is separately budgeted.

The same bound covers the fixed-key miss control. Numeric bulk adds its aligned 128-byte pointer array and at most 32 aligned 32-byte leaves: with the same index bound, 3,528 bytes fit 4 KiB. Nested leaves need at most 32 × 276 = 8,832 bytes, plus 2,376 index bytes, fitting **12 KiB/batch**. These are conservative allocation bounds for these exact fixtures, not measured memory savings.

Use **one parent Arena per calibration child and one per measurement child**, accumulating every phase's allocations. Retain original and phase-boundary snapshots, including every warm batch and pilot, through process exit. No earlier Arena, snapshot, leaf, or dependency is assumed reclaimed. Configure public future-Arena limits before creation; never call a heap rewind, private allocator reset, compaction, or Arena reset between timed phases. Native growth/page-zeroing during the burst stays timed.

- Object/miss/primitive: common observation count ceiling **65,536 batches**; four `N/8` warmups plus `N` observations are at most **98,304 batches**, or **384 MiB** payload.
- Nested: observation ceiling **16,384 batches**; all five measurement phases total at most **24,576 batches**, or **288 MiB** payload.
- Count-planning calibration has **no probes**: object/miss/primitive use four 4,096-batch warmups plus three 8,192-batch pilots, **40,960 total batches / 160 MiB**; nested uses four 1,024-batch warmups plus three 2,048-batch pilots, **10,240 batches / 120 MiB**. These totals include every phase, with the same setup, prefix, page-rounding, dependency, retained-snapshot, and JS/engine allowances below. Reject a next phase before launch if it would exceed its fixed cumulative budget.
- Reserve **2 MiB additional parent payload** for setup. The 2,048 seed keys have unique full hashes; each seed leaf is 32 bytes and a conservative eight 72-byte branches per key bounds their index construction. Including a 4 KiB initial primary batch gives 1,249,280 bytes, below the allowance. Assert actual untimed used bytes before admission. The parent prefix is 64 KiB; page rounding adds less than 64 KiB, with a 128 KiB minimum backing. The nested dependency has its own public **2 MiB maximum**, includes both child snapshots, and remains retained. Prefix/scratch/staging live inside that backing, not an extra allocation. Thus source-bounded retained native backing is below **389 MiB** even using the largest payload bound, setup allowance, rounding, and dependency allowance together.
- Set the parent public maximum to **512 MiB**, total actual Arena-backing safety cap to **512 MiB**, and original-process-group RSS cap to **1,536 MiB**. Require at least **3 GiB available host memory** before admission. The gap between the conservative native bound and RSS cap is an explicit allowance for JS fixtures, validation objects, cache entries, retained wrappers, module/native instances, engine heaps/JIT, and supervision. Source cannot prove their exact RSS or peak; authenticate fixture counts and native used/capacity, retain sampled RSS, and stop on the cap. The allowance is not a claim that GC will free native memory. No forced GC is planned; setup and validation happen outside timers, while natural GC occurring within a phase remains included.

The fresh-import child retains its full prebuilt 5,000-record fixture, original/final snapshots, Arena, and engine overhead. Its `key-0` through `key-4999` hashes are distinct and keys at most eight bytes. Require the existing feature fixture's encoded records to be at most 512 bytes before admission. Then each leaf is at most 536 bytes, with a conservative eight 72-byte index branches per key: **5,560,000 payload bytes** plus prefix/page rounding, below a public **16 MiB Arena maximum**. Its 5,000 pointers fit the existing scratch. This separate bound does not use the special 32-key topology. JS fixture/validation/engine overhead remains under the same RSS cap, without an exact source-derived RSS claim.

Separate endpoint payload budgets follow; add less than 128 KiB per parent for its prefix/minimum/page rounding. The nested child allocates exactly two 28-byte leaves, with no index branch, and retains one 128 KiB backing for both snapshots. No endpoint creates other Arenas during timed phases.

## Count planning, measurement, or parking

The inherited geometric method is unsuitable here. Its one-second calibration warmup alone exceeds 98,304 batches at the 7.63-microsecond rate that would produce a valid 500 ms primary observation. Including geometric steps, eight minimum warm batches, and three pilots, its ideal constant-rate feasibility thresholds are 24.4140625 microseconds/batch for object/miss/primitive and 97.65625 for nested. Their maximum observations would already last 1.6 seconds. The retained first version and arithmetic record show the complete counts. Do not build that calibration unchanged or claim that the observation allocation ceiling makes it feasible.

The minimal alternative is the **fixed-operation count planner above**. Require four positive warmup durations and three pilots each at least **20 ms**. This prospective planning-only floor replaces the inherited calibration's 100 ms pilot floor and one-second warmup; the separate measured-child gates do not change. Both arms must complete their fixed seven phases within all limits. A short pilot makes planning unresolved; do not lengthen it, restart, or add phases. Retain all planner durations and allocation rows, but do not infer a speedup from them.

For each engine/endpoint, take the fastest rate among both arms' six valid pilots, round up its 1.5-second target count to a multiple of eight, then use **min(target count, endpoint observation ceiling)** symmetrically. Record the target, selected count, and cap flag; freeze all counts before measured subjects. A 1.5-second target is a preference, not a memory requirement. Every measured child still requires four `N/8` warmups totaling at least **350 ms**, followed by one `N` observation lasting at least **500 ms**. All paired/noise/loss gates below remain intact. A capped count can qualify only by satisfying every gate; a short capped cell stays unresolved without extra samples or a larger ceiling.

At the primary ceiling, observation and warmup duration floors require constant rates of at least **7.63** and **10.68 microseconds/batch**, respectively. The fixed 8,192-batch planner pilots need only **2.44 microseconds/batch** to reach 20 ms. Nested thresholds are **30.52**, **42.72**, and **9.77 microseconds/batch**. Thus planning no longer imposes the stronger constant-rate threshold; these are arithmetic comparisons, not predictions. Fixed work and 20 ms pilots do not establish settled JIT tiers. Fresh measured processes may tier or collect differently; inaccurate planning can leave a cell short, noisy, or capped despite valid planning. The fixed measured warmup and repeated-arm drift gates constrain, but cannot prove away, that limitation.

**Choice:** parking now is defensible because the change saves only one helper and, below cache limits, one Map membership check amid unchanged JSON/allocation work. The fresh-import guard may remain unresolved, so even a primary benefit would not establish broad regression clearance. If this lead merits another bounded study after the active cohorts, prefer independent review of the fixed-operation planner; it offers a finite way to ask the question without a memory-invalid calibration. No source evidence shows the savings are material. A failed feasibility or stability gate should end that cohort, not start a search for friendlier counts.

## Paired decisions and evidence boundary

Reuse four independent four-process blocks: ABBA in blocks 0/2, BAAB in 1/3, deterministic engine/endpoint rotation, sequential subjects and verified cleanup. Never pool engines. Measurement children retain the accepted 15-second/1,536-MiB cap; calibration children 25 seconds/1,536 MiB. This document does not release them.

For the sole primary, require all 16 observations/warmups valid, all four block ratios favorable, and the one-sided 97.5% t upper candidate/baseline ratio bound at most 0.95 in both engines (df 3; two-engine Bonferroni). Preserve the accepted noise gates: larger median absolute repeated-arm log drift D at most log(1.05), pooled-eight interpolated p90 at most log(1.15), and conservative log gain greater than 2D. Complete/stable warm controls get pointwise one-sided 95% loss bounds: lower bound above 1.02 blocks advancement; upper bound at most 1.02 supports only that scoped guard. Crossing, short, capped, unstable, incomplete, and fresh-import diagnostic outcomes stay visible. No reduced-block inference, outlier removal, retry, extra block, or promotion of a secondary result.
