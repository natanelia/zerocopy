# Shared-memory sharded publication baseline — 26 Nov 2026

Previous serial candidate #98 was merged as 50b06167909ff1398d293948c4a82c5f7bea5863 after exact-head CI, CodeRabbit review with no actionable findings, and the maintainer's scope-specific approval. No tag or npm release. Transferable copies benefit copy-mode only; the next lane is actual SharedArrayBuffer transport.

Hypothesis: in multi-layer/tile applications a sparse edit to one of many independently retained arenas may cause every worker to reconstruct an Arena/WASM instance for every incoming descriptor, even when the root and backing memory are unchanged. Current `connectSharedSession` reconstructs via `initWorker` then preserves old top-level identities. The earlier worker-arena benchmark measured isolated attach/re-export, #61 constructor dispatch measured local metadata, and worker-record-descriptors measured publication without connected workers. None establishes that this cost dominates repeated useful answers in actual two-worker sessions after #97/#98. No production change until baseline evidence shows a meaningful opportunity.

Fixed main 50b06167909ff1398d293948c4a82c5f7bea5863. Website catalog records distributed across named tile maps, two real Node workers, explicit `copy:false`. 100k records: one map, 64 maps in one shared arena, and 64 separate arenas (same keys/values and shard distribution for the latter pair). 10k with 64 maps in one/distinct arenas; 1k single and 16 separate as small controls. Each trial starts a fresh process, attaches workers, makes eight 25-record (or all available records if a small shard has fewer than 25) sparse updates rotating across shards, waits for both useful responses **and** acknowledgements before the next publication, and retains versions 0, 4 and 8. The 100-read probe includes edited records and distributed reads. Check every probe value, unchanged top-level identity, shared transport handles/copy bytes, reader read-only behavior and all records of each retained revision in the owner and both readers. Initial attachment is measured from connection request, not from process start. Reader receipt-to-accept duration includes protocol processing, scheduling, descriptor reconstruction and callback dispatch; it is not an isolated WASM instantiation timer. Synchronous publish, first connection, edit, query and complete time to both useful responses reported separately. The two 64-shard layouts isolate the effect of independently allocated arenas from top-level field count more closely than comparing against a single map, but layout and allocator effects may still differ.

One excluded warmup pair and four alternating measured identical-build A/A pairs per case; different process per arm, no artificial GC during measurements. Preserve all raw outputs, runtime/build hashes and errors. Arena used bytes are summed once per distinct arena in the current payload; process memory is sampled only, not peak RSS/GC or per-worker RSS. No cross-runtime or candidate speedup claims yet. If meaningful end-to-end overhead is found, profile the specific reader/owner phase before choosing a change; do not cache an Arena or registry solely by id or mutate historical heap bounds. Validate growth, changed dependencies, copied sessions and historical snapshots in any subsequent candidate. If the real workload does not justify it, record the result and move to another shared-memory opportunity. Reproduce with `bun install --frozen-lockfile && bun run build:wasm && bun run build:browser && node proofs/shared-session-shards-20261126.mjs results`. Read-only bounded proof branch; no preview, production PR, merge or release authorized for this candidate.

## Attribution and experimental candidate — 26 November

[Attribution run 45819549501](https://github.com/natanelia/zerocopy/actions/runs/45819549501), [raw evidence](https://github.com/natanelia/zerocopy/actions/runs/45819549501/artifacts/15117521123). Parsed 40 verified sessions / 320 publications (256 measured). In the instrumented 100k/64 distinct layout, every repeated attachment constructs 64 native WASM instances per reader, with median synchronous construction 2.142 ms out of 2.491 ms receipt-to-accept (ratio of medians, not a per-sample causal estimate). At 10k/64 distinct: 2.105 ms out of 2.467 ms. 100k/64 one-arena: one instance, 0.053 ms construction. Uninstrumented 100k/64 distinct round trip 4.957 ms; instrumented 4.233 ms, illustrating scheduling and measurement perturbation; don't use these as paired optimization gains. This confirms the construction count and identifies a substantial avoidable phase.

Experimental runtime change limited to Arena: defer native kernel instantiation for read-only repeated attachments only when the previous frame's same-ID arena points to the exact same already validated WebAssembly.Memory object. The initial frame, new memories, copied transport and writers remain eager. Every new frame still has independent arena objects, registry, caches and heap-end captured from that frame; no native instance or mutable bound is shared. Materialize on the first native-kernel access as an own data property, preserving native identity and honoring explicit kernel replacement. This may shift work to queries, not remove it for changed/all-read arenas, so actual round trips are the acceptance metric. Deferred native allocation failure timing and getter/data-property transitions warrant review before production. Re-export may trigger materialization; do not claim improvement there.

Paired candidate screen on Node using the existing actual two-worker fixture, six measured alternating AB and AA pairs per layout, one warmup each. Five cases include 1k/100k single-map controls, 100k 64 maps one arena, and 10k/100k 64 distinct arenas. Separate instrumented samples verify the mechanism, not timed speedups. Verify all retained data, top-level identity, transport and read-only behavior, plus exact heap bounds, nested and re-exported values, memory growth, distinct backing memories with duplicate IDs, native identity and copy controls in focused tests. If successful, qualify browser/Bun and dense/churn/reader scan controls separately; reject any material default or read regression. No production PR or publication authorized for this candidate.
