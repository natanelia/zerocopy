## Fixed measured work

Both Linux x64 Node 22.23.3 and Bun 1.4.2 import their freshly built official `dist/shared.js`. Every cell reports nanoseconds per public call including common indexing and a preallocated result store. Whole compact/compactMany calls include target Arena/instance creation, copying and construction. No count is divided by collection size; there is no loop subtraction. Setup, input creation, cache priming/inspection, GC, output observations, validation, hashes and serialization are outside the timed body.

Values initially equal each key's input index; changed values add 1,000,000. The group object is `{text: 'x'.repeat(65525)}`: its JSON encoding, including syntax, is exactly 65,536 ASCII bytes. Group work is one public call on five named descriptors, with a repeated descriptor and nested alias. Its metadata `size` is the 256-key principal root, not a per-entry divisor or the count of unique copied records.

Inputs use public constructors and immutable sets. Full-compaction sources retain their ordinary final canonical/journal state: 4,096 and 256-entry sorted sources finish canonical; tiny and 64-entry sources include normal pending entries. Compaction does not invoke a custom comparator in these timing fixtures. Other comparators, sets, Unicode/aliases, nested types, cache thresholds, deep trees and failure boundaries remain in the separately preserved correctness corpus and new small repository regressions, rather than expanding the timing matrix.

Every full-compaction result remains strongly retained in its own preallocated output slot through validation. The nested group's roots share one new owner and are counted once. Results never feed subsequent compact calls or writes. The read case constructs exactly calls/1,024 compacted owners outside timing, asserts empty key/read/value caches without performing a lookup, then queries all 1,024 distinct keys once in each owner. Numeric read results remain in the output array. It does not repeat a warmed sweep in the same owner.

The write case creates one compacted owner outside timing, publicly reads all 1,024 keys and verifies exact-source-root primitive slots. This is the **initially primed** state. The loop calls the same retained root's `.set` every time with a different value from that source. Its outputs share that owner and all survive to validation; no output root feeds another measured write. The harness records the natural post-body slot state without forcing it back to the initial state. It validates each result's changed key and one distinct unchanged key, plus complete first/last output entries and the retained source bytes. Identity assertions explicitly re-read the retained source after other validation reads.

## Bounded ownership and allocation

The maximum **sum of distinct live backing capacities** is 33,554,432 bytes (32 MiB), including all retained sources, measured outputs and both default writers. Original source/default owners additionally have an 8,388,608-byte sum ceiling. Every Arena has a 67,108,864-byte configured growth limit. These are different limits. The subject checks a prospective result-owner envelope before the body and actual summed capacities afterward; every output remains live until that check. Unique owners, total backing, used bytes and allocation records are reported separately. No cap silently discards an output or shortens a ladder.

The source-derived numeric sorted bound is: 65,536-byte header + sum of four-byte-aligned `(16 + UTF-8 key bytes + 8)` leaves + up to seven alignment bytes + eight-byte-aligned `4*n` pointer input + at most `(n-1)*88` branch bytes, rounded up to 65,536-byte pages and at least two pages. This uses the unchanged owned builder's at-most-one branch allocation per distinct inserted leaf after the first; a radix branch has at most 17 children. The candidate fits the same envelope. It is an upper bound, not a measured count.

At the declared maxima the full-compaction output envelopes are 16 MiB tiny/binary/prefix/fallback, 18 MiB decimal, 12 MiB long-prefix, 16 MiB group and 16 MiB HAMT. Add the at-most-8-MiB source sum. Read owners total at most 12 MiB plus sources. Repeated writes allocate at most 56 bytes per four-byte-key changed write (28-byte leaf plus alignment and a one-entry journal); their one canonical owner fits 4 MiB plus original sources. Each write starts from the same canonical root, so no journal result is folded by the next write. The group ceiling includes two sorted indexes, shared 257 numeric leaves, two ordinary single-leaf maps, inputs, JSON and a conservative descriptor allowance. The HAMT ceiling exceeds seven 32-way partition levels per key plus leaves/inputs/collisions; it is not an assertion of that many allocations.

For standalone sorted numeric outputs, the known leaf/input region delimits a branch-only allocation suffix. The census reports copied leaf bytes, input/alignment bytes, all allocated branch records, reachable branches, abandoned records, total used bytes and backing. The strict candidate must have no abandoned branches. Binary/prefix/tiny and fallback controls must retain equal counts across arms. The mixed group reports used/backing, unique reachable nodes/leaves and encoded payload/descriptor lengths; it does not infer a generic interleaved allocation history. HAMT reports used/backing/reachable leaves without inventing a raw branch classification. Read/write owners have their own census/growth records.

All bytes above describe logical allocation/backing. JavaScript retained heap, physical residency, virtual reservations and peak coexistence are not measured gains. GC occurs symmetrically before setup, after setup and after releasing the chunk; collection is not a physical-memory guarantee. Subject/controller RSS are safety checks: 536,870,912 and 268,435,456 bytes, sampled every 100 ms. Combined stdout/stderr is capped at 8,388,608 bytes. Linux `process.resourceUsage().maxRSS` uses KiB and its separately named conversion multiplies by 1,024; `process.memoryUsage()` and backing capacities use bytes.

## Controller, statistics and partial evidence

`controller.py` and `math.mjs` are copied byte-for-byte from the accepted native-key controller, via independently accepted batch-clear revision 2. The CI adapter replaces the copied controller's historical admission callback with fresh exact-arm admission. Do not use the bare controller's old native-key admission as this study's gate. Both actual arm compiler directories are hashed before build, compared with each other and the 272-file reviewed compiler manifest, then included individually in the final tools manifest. Source, tools, builds and harness are checked before/after each child and at completion.

There are four calibration subjects and 32 measurement subjects. The four blocks use BCCB, CBBC, BCCB, CBBC, alternating Node/Bun order each block. Calibration runs 32 maximum-work warmups and three samples at every finite level for both arms. It selects the smallest common level whose two medians both reach 12 ms; otherwise it keeps the maximum and flags the floor. No new level, pilot retry or adaptive warmup is permitted. Each measurement subject runs 32 warmups and seven samples per cell. Floors are 5 ms per measured body and 200 ms total warmup body time; last-eight/prior-eight warmup median drift above 10% or relative MAD above 5% is a flag.

Each process estimator is its seven-sample median. For a block, `d = (ln C0 + ln C1 - ln B0 - ln B1)/2`. The four block values are the inferential units; the pointwise 95% interval is `exp(mean(d) ± 3.182446305284263 * sampleSD(d)/2)`. A/A diagnostics use the second/first same-arm process ratio **within each quartet**. They are dependent repeated-arm diagnostics, not an independent A/A experiment. Any >5% block discrepancy or A/A interval excluding 1 is flagged; lack of a flag does not establish 2% equivalence.

Any flag makes a cell inconclusive. Clean lower CI >1.02 supports a material loss; clean upper CI <0.95 supports a worthwhile gain; clean upper CI <1.02 excludes a 2% loss pointwise. No target gain offsets an adverse control, and no pooled result replaces these twenty engine/case cells. Incomplete whole-run admission or absent final source verification blocks supported conclusions even if some complete ratios exist.

Each body emits one compact `body-observation` immediately after the clock stops and before validation, with a stable slot/sequence ID. A later validated case row references that ID; report/admission checks the linkage. Raw observations are explicitly unvalidated, omit nested output arrays and cannot satisfy a successful subject or whole-run gate. If a body itself throws, that unfinished body's duration is unavailable. Completed earlier observation lines and original partial files remain; there is no reconstructed duration or replacement run.

Per-child safety budgets are 180 seconds calibration, 90 seconds measurement or untimed. The whole screen is 2,100 seconds plus the common two-second termination/reap grace. These limits include setup, GC, validation and output, not just bodies. Cleanup verifies owned process-group absence. Failure, interruption, exhaustion, floor and pending/not-run slots remain in the original directory; nothing resumes or overwrites it. Unresolved owned writers prevent later subjects and verified archive claims. The ten-case packet is not guaranteed to finish within its fixed budget.
