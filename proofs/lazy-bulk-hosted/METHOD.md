# Prospective hosted timing method: lazy bulk encoding tables

This is one prospective GitHub-hosted ubuntu-24.04 cohort. Both arms are exact archives of commit afdffdcfcbd61013f120de82411c0c4a6b2d1e0e (tree eb3bd4217f132e13b01c42f9b9c6bdc5aa92afab). The candidate differs only in primitive/string private Unicode side-table allocation; candidate arena.ts SHA-256 is aee54d67ba1e1326d84f90978dd1ed91d365b69fd70bda6c189c03729af3b015. Generic-object staging is present in both arms. The host must pass exact-source correctness before the screen. No local timing exists and no cross-host equivalence is claimed. Runtime binaries, resolved dependencies, CPU, OS, source, native and portable outputs are recorded.

## Workloads and claim

Eight endpoints, fixed before calibration:

1. ASCII string setMany, 8 records: primary choice A.
2. ASCII string setMany, 64 records: primary choice B.
3. ASCII number setMany, 64 records: changed secondary endpoint and regression guard.
4. String setMany, 64 records, Unicode on both sides of every row: adverse control.
5. String setMany, 64 records, first Unicode key and value at the final deduplicated row: adverse control.
6. ASCII string scalar set: unchanged control.
7. Empty setMany: unchanged control with a fixed operation cap.
8. Small plain-object setMany, 64 records: unchanged control; identical current-main generic-object staging in both arms.

Use deterministic short keys and short values, unique keys after normalization, and two prebuilt value phases that change every existing entry. The evolving map retains the same cardinality; scalar writes cycle the same 64 keys, and the value phase changes by full key cycle: floor(writeIndex / 64) modulo 2. The untimed smoke must assert that every scalar call changes the prior value, including across two complete key cycles. Inputs are prepared before measurement. Each writer starts from a seeded map, retains that initial root, and updates the latest map through public APIs. Record a root/size checksum and validate initial/final content afterward. The claim is time per public update within a bounded writer lifecycle, including reset/construction/seeding, map wrappers, native growth, and natural GC occurring inside the timed window. It is not an isolated encoding-helper claim or an indefinitely growing arena. Fixture generation, module startup, explicit validation, and supervised process startup are outside timing. No forced GC.

## Bounded writer epochs

Each measurement child handles exactly one engine/arm/endpoint observation. Set the public memory maximum to 64 MiB before constructing any arena. Every arena creation in every child debits a single admission ledger, including fixture probes, calibration probes, warmup, seeding, and measured epochs. Admit at most 10 arenas per child in total, so the sum of configured WASM linear-memory maxima cannot exceed 640 MiB, even if none of those arenas has been collected. Measured children allow at most 2 warmup plus 8 timed epochs within that same total; calibration and smoke do not receive an extra allowance. This is not a bound on total engine virtual reservations or RSS, which also include guard regions and JavaScript overhead. An independent 1.5 GiB process-group RSS cap and 20 second child deadline cover the runtime process. Keep only the current initial root and latest root live, and retain scalar records rather than previous maps.

Use a 32 MiB allocated-byte budget per writer epoch, including seeding and alignment; the 64 MiB native maximum is a hard safety backstop. In each of the four engine/arm smoke children, use exactly one arena per endpoint for its fixture checks and 128-write sizing probe, totaling eight arenas within the ten-arena ledger. These probes estimate native deltas. After all four smoke children complete, the controller derives each engine/endpoint's common epoch write limit from the larger arm's observed maximum, with seeding/alignment debit and a count rounded down to a multiple of 256. This common layout is fixed before any of the 32 calibration children starts. This estimate is explicitly not a proof or safety bound for future allocations. Validate every actual epoch's used/capacity before and after it. If its allocated bytes exceed 32 MiB, its native maximum traps, fewer than 256 writes fit, its admission count exceeds 10, or more than 8 timed epochs would be required, classify it as budget-invalid/capped and stop that cell. Do not treat the partial elapsed time as a valid sample, silently reduce counts, or replay it. Counts/layout are identical across arms; any observed native-byte disagreement also invalidates the pair. For scalar phases, epoch write counts are multiples of 256 and therefore whole 64-key cycles. Zero-allocation empty calls retain their independent operation cap.

Timers cover reset, construction, seeding and the complete fixed update loop; allocation inspection and initial/final validation are outside timing. Thus unexpected allocation growth has a finite native backstop even if it occurs between inspections, while over-budget work cannot enter a valid timing result. The smoke and calibration controller must reconcile total admissions, all allocated bytes, and the sum of admitted WASM linear-memory maxima across all phases before it seals counts.

## Smoke, calibration, and frozen samples

Before any calibration: one pure fixture/metadata smoke without a library import, then an untimed smoke in each of the four engine/arm combinations. Check the eight IDs/counts, normalized survivor shapes, Unicode table positions, alternating final values, retained roots, operation accounting, and raw-result round trip. Any fixture or accounting failure stops before timing.

Calibration is one bounded process per engine/arm/endpoint. Fixed geometric probe counts start at 1024 and multiply by 4, stop at the first probe reaching 25 ms, and never exceed 1,048,576 calls, the writer/memory limits, or the child deadline. Use the two arms' faster observed rate to choose a common count targeting 250 ms, rounded to the fixed epoch layout. Calibration chooses common total counts as multiples of 256 within the already fixed epoch write limits, allowing a final partial epoch of at least 256 writes; no measured process chooses its own count. Counts, complete epoch layouts, and maximum allocation are then sealed before measured samples. There is no calibration restart. If either arm cannot reach the probe duration or support a common count within the operation, epoch, admission, memory, or time limits, seal that engine/endpoint as calibration-short/capped; retain both raw pilot records and mark all its scheduled measurements not-run. Never derive counts from the surviving arm alone. Empty uses at most 1,048,576 calls in every phase; if this cannot provide an adequate duration, report it as short rather than escalating constant-foldable loops.

Use exactly 4 paired blocks per engine/endpoint. Each block launches four fresh processes, ABBA on even blocks and BAAB on odd blocks. Both arms receive identical counts and fixtures. Alternate engine order and rotate the eight endpoint positions deterministically. Each process has bounded warmup targeting 50 ms, followed by one measured observation targeting 250 ms. A measured observation below 150 ms or incomplete bounded warmup is short; no count adjustment or replacement sample follows. Empty is subject to the same duration rule and may remain an explicitly unresolved diagnostic. All statuses remain in the table.

Maximum 256 measurement children plus 32 calibration children, 4 untimed subject-smoke children and 1 pure smoke. A 600 second whole-run cap includes pre/post authentication, analysis and cleanup; reserve 15 seconds for cleanup. Original-group cleanup must be confirmed before any next process. Short or cleanly capped cells remain visible while other predeclared cells continue; a cleanup uncertainty or metadata/semantic mismatch stops the gate. Missing work at the whole cap is not-run, never a pass. No retries, added blocks, endpoint replacement, or resampling for narrower bounds.

## Fixed analysis and decision rules

For each block, compute the log ratio of the geometric mean candidate times to geometric mean baseline times. Use the four block ratios as the independent units, with Student-t degrees of freedom 3; the resulting wide uncertainty is an honest limitation of this first screen. Student-t/Bonferroni intervals are local modeled intervals, conditional on independent approximately normal block log ratios; they do not establish behavior on other hosts or workloads. Report every raw arm time, all block ratios, geometric ratio, uncertainty interval, sample duration, repeated-arm drift, native bytes, RSS/cap status and checksums. Do not average engines or choose a different primary per engine.

A primary claim requires the same one of endpoints 1/2 to show at least 5% gain in both engines: the upper one-sided 98.75% Student-t confidence bound on candidate/baseline must be at most 0.95 in each engine. This Bonferroni choice covers the four predeclared primary engine/endpoint comparisons. All 4 complete valid blocks are required for any confidence or regression bound. Short, capped, or incomplete cells retain raw/descriptive evidence only; do not compute reduced-block inference or a df 3 bound for them. No later blocks are added to rescue an inconclusive screen.

Within each engine/endpoint, compute absolute log differences between repeated baseline arms and between repeated candidate arms. Define typical drift D as the maximum of the baseline and candidate medians (four values each). Require D <= log(1.05), and the pooled eight-value 90th percentile <= log(1.15), defined after ascending sort as x[6] + 0.3 * (x[7] - x[6]) using zero-based indices, equivalent to interpolation at index 0.9 * (8 - 1) = 6.3; otherwise mark unstable. A primary benefit additionally requires its conservative log-gain bound, defined as the negative of the upper confidence bound on log(candidate/baseline), to exceed 2D. This ties the accepted effect to observed repeated-arm drift rather than treating a fixed range cutoff as sufficient. These prespecified diagnostics do not remove outliers; retain every observation even when it fails.

For every endpoint, including both primary choices, also report pointwise 95% one-sided bounds for the regression guard. The other primary remains a regression guard even if one qualifies in both engines. A lower bound above 1.02 establishes a meaningful regression and blocks promotion. An upper bound at or below 1.02 with valid duration/stability supports only that scoped control. An interval crossing 1.02, unstable, short, capped, or incomplete control stays unresolved. These pointwise controls cannot establish universal no-regression clearance. Any promotion decision must distinguish a supported primary benefit from unresolved controls and cannot conceal them. If neither identical primary qualifies in both engines, the experiment does not support the requested improvement. No threshold changes after calibration.

## Evidence validity

An arbitrary WebAssembly.RuntimeError is an unexpected failure: its cause is not proved to be a memory maximum. Explicit admission and used-byte checks alone produce recoverable budget outcomes. Final controller status takes precedence over all statistical claims; an interrupted, expired, unauthenticated, or otherwise failed finalization suppresses qualifying inference and preserves descriptive evidence. Matching-count calibration probes must agree on native allocation, content, and operation accounting, including partial evidence when either arm is short or capped. Different calibration counts are not compared as equal allocations. Every observation retains its available raw output, duration, warmup, ledger, and identity. Incomplete and unstable cells remain visible.
