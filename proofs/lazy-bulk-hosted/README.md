# Lazy bulk table hosted screen

One prospective hosted experiment compares exact main `afdffdcfcbd61013f120de82411c0c4a6b2d1e0e` against the small primitive/string Unicode-side-table allocation patch in `candidate.patch`. The repository's production source is unchanged by this proof. Both runtime subjects are materialized from the authenticated Git object; only the candidate's `arena.ts` receives the patch. Existing generic-object staging is identical in both arms.

This is a new GitHub-hosted `ubuntu-24.04` cohort, with Node 22.23.3 and Bun 1.4.2. It claims neither local timing nor cross-host equivalence. Runtime binary identities and hashes, package versions and dependency-file hashes, CPU, OS, native output hashes and portable output files are retained. The exact base has no dependency lockfile; the hosted resolution happens once with install scripts disabled, and its resulting lockfile and complete installed-file manifest are preserved. TypeScript 5.9.3, Vitest 4.1.11 and AssemblyScript 0.28.20 are checked before any subject runs. A setup or version mismatch stops the job.

## Workflow

The workflow is scoped to `agent/lazy-bulk-tables-hosted-screen-20261011`, requires the first run attempt, and accepts only a single proof commit directly atop the pinned source commit. It checks the complete changed-path allowlist and the payload hashes. It grants only `contents: read`, uses the repository's established checkout/setup/upload actions, does not persist checkout credentials, and has no publishing or deployment step.

Preparation archives all 502 source files twice, authenticates every file, applies and authenticates the candidate, and checks that all native compiler inputs are identical. It compiles native modules once in the baseline and shares those authenticated outputs with the candidate. It does not assume that hosted native outputs equal outputs from another machine. Dependency installation has a 180-second / 2-GiB cap and native compilation a 120-second / 2-GiB cap, using the same process-group supervisor as the experiment. Setup must finish within 360 seconds.

The unchanged focused correctness corpus then runs in both engines and arms: fixture metadata smoke, two portable builds, two declaration builds, exact source/emitter/declaration/WASM audit, four corpus runs and retained-output reconciliation. That is eleven commands, capped at 360 seconds total with 8 seconds reserved for cleanup. Build, declaration and corpus children keep their 60-second / 2-GiB caps; smoke, audit and reconciliation keep 30 seconds / 512 MiB. The corpus checks the five semantic groups, retained roots and bytes, callback/reentry behavior, errors, growth, and seven snapshots through both shared and copied real Node Workers. Only all eleven passing, cleanly terminated commands and authenticated outputs allow timing.

The [method](METHOD.md) fixes eight endpoints, two engines, four ABBA/BAAB blocks, 256 measurement children, 32 calibration children, four subject-smoke children and one pure fixture smoke. The original 600-second timing window includes input authentication, analysis and cleanup, with 15 seconds reserved for cleanup. Every timing child is capped at 20 seconds and 1.5 GiB process-group RSS; every child shares a ten-arena admission ledger. Thresholds, count calibration, paired ordering, drift definitions, stop rules and incomplete-result handling remain fixed. No retry, extra block, cross-platform matrix or favorable-result resampling is part of this workflow.

The total Actions job is bounded to 25 minutes; step deadlines are outer safety limits and do not extend the controllers' internal limits. Failed steps prevent dependent stages. Setup forwards SIGINT/SIGTERM to its active cleanup supervisor, waits for its bounded original-group cleanup, records interruption or explicit uncertainty, and blocks later stages. Cancellation, failed setup/correctness, unexpected WASM traps, cleanup uncertainty, mismatched bytes, missing terminal results or failed final authentication never yield a qualifying result. A repeated workflow attempt or a later proof commit cannot run this screen. A manual reconstruction or different branch is a different proposed experiment, not an automatic fallback.

## Evidence

The artifact retains the authenticated base source archive, host/native/build/input manifests, original setup and correctness logs and receipts, built portable modules and declarations, all available timing requests/raw results/receipts, frozen counts, final analysis and an artifact SHA-256 manifest. All workload data are synthetic. No private notes, review or authorization records, recovery archives, package cache, environment dump or credentials belong in this payload.

`timing/execution/RESULT.json` is the controller terminal record; `ANALYSIS.json` is the complete result table. A successful Actions job only establishes that the screen completed. Benefit needs the same predeclared primary to qualify in both engines under the method's effect and noise rules. Adverse or unresolved controls remain visible, and a statistical result is not production promotion. No result exists in this source-only preparation.
