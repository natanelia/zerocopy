## Question and fixed cases

Does the exact three-line `Arena.findUncached` guard improve ordinary public missing-key reads while preserving nonzero-child, cached-hit, empty and startup behavior? It avoids one native call only when the cached child is zero. Nonzero lookups gain a JavaScript branch. No memory-saving claim is proposed.

All cases use numeric `SharedMap` values and ordinary sequential eight-character ASCII identifiers: `k` followed by seven zero-padded decimal digits. Values are identifier number plus one. No hash-lane search, key rejection, filtering or favorable-prefix selection is permitted. `FIXTURES.json` freezes complete formulas, counts, query order and expansion hashes.

| ID | Public operation and fixture | Role and prospective coverage |
| --- | --- | --- |
| P1 | `get`; 128 entries, 4,096 absent identifiers | Sole qualifying primary; 2,534/4,096 probes (61.865234375%) have zero children; every operation reaches `findUncached` |
| P2 | `has`; 256 entries, the same 4,096 absent identifiers | Supporting second miss scenario; 1,480/4,096 probes (36.1328125%) have zero children; every operation reaches `findUncached` |
| C1 | `get`; 8,192 entries, the same absent identifiers | Dense nonzero miss control; all 256 eight-bit prefixes populated, hence 100% nonzero-child coverage |
| C2 | `get`; 32,768 entries; publicly read entries 0–16,383 once, then query entries 16,384–32,767 | **Naturally cache-saturated successful reads**, not ordinary warm hits: 16,384 × 8 = 131,072 key characters and 131,072 numeric-value bytes. Entry/character limits fill exactly; the queried tail cannot enter the primitive value cache. All timed reads reach the 12-bit directory and a nonzero child |
| C3 | `get`; 128 entries; publicly read all 128 once, then repeat all 128 | Ordinary cached successful-read control; 100% bypasses `findUncached` |

These six cases are the complete steady-state screen. P2 cannot replace P1 after seeing results. There is no broad workload search. Static coverage is not instrumented runtime-call counting. The first-nibble populations in P1/P2 are all at least 7/15, so missing eight-bit prefixes cannot be disguised by an earlier singleton leaf. C2 coverage follows public routing and cache arithmetic, not private inspection. The frozen static computation is described in `STATIC-COVERAGE.json`.

## Readiness, resolution and analysis

Record every warmup and measured batch, actual operation count, checksum, absolute milliseconds and nanoseconds/read. Outside the measured intervals, collect 10,000 adjacent timer deltas and 1,000 empty timer-pair costs separately for the actual clock domains: the supervisor clock used for spawn-to-ready, and each child clock used for import-to-ready and read batches. For each clock, record min-positive increment, median/p99 deltas and median pair cost. Every measured read batch must last at least 8 ms and at least 1,000 times both its own child clock's min-positive increment and median timer-pair cost. Missing/zero usable clock estimates or failed floors make the cell unresolved. At the target, four measured batches supply 80 ms per process; the independent experimental units remain the 16 process pairs.

Readiness requires the final four of the eight warmup batches to have sample CV ≤5%, and their last-two mean to differ from their first-two mean by ≤3%. Measured batches require CV ≤5% and last-two versus first-two mean drift ≤5%. Apply these rules to both variants without extending or deleting observations. A failed process remains in the raw results and makes its cell unresolved. Startup has no warmup by definition: report its absolute times and variance; each observation must exceed 1,000 increments/costs from its actual measurement clock (supervisor for spawn-to-ready, child for import-to-ready), and its interval must resolve the control bound below. Short/noisy startup is unresolved.

For each steady case/engine/round, use total time across the four measured batches divided by 4N, then log(candidate/baseline). Across the 16 paired logs, report the geometric mean ratio and a two-sided 95% Student-t interval (df=15, t=2.131449545559323). Publish arithmetic mean, median, SD, CV, minimum and maximum absolute batch/process times for each variant, all 16 paired ratios and interval endpoints. For each startup metric, average the six case-paired log ratios within each round, then use the same 16-block interval; also publish all constituent startup times. This avoids pretending the six starts in one round are independent rounds. Report intervals as latency ratios and gains; do not mix engines or workloads.

## Finite work and stopping

The one-case calibration/performance fixture cap remains 32,768 stored entries and at most 4,096 extra query strings, with the separately fixed startup smoke; C2 queries reuse its stored tail keys. The four validators instead have a separately labeled validation-only bound: all six fixture input arrays total 41,472 entries; six fork chains perform exactly twelve sets and six deletes. Separately allow six constructor-empty handles before `setMany`, plus the conservative twenty-four original/fork-operation result slots including intermediates: at most thirty writer snapshot handles, twelve attached-reader handles and two startup handles (44 total), without assuming any collection. Original/final writer sizes sum to 82,946; mirrored reader sizes also sum to 82,946; the startup singleton adds one. These are logical snapshot memberships, not physical leaf-allocation or memory estimates. The same 4,096 absent-key strings may be shared.

Each validator retains exactly twenty-four copied payload buffers (twelve transport before-images plus twelve after-read images) and twelve read-only reader-memory buffers, with no separate comparison buffers. Their aggregate committed buffer bytes must stay within **256 MiB (268,435,456 bytes)**. Before every `copy: true`, obtain the source used length through a public `copy: false` descriptor and precheck the cumulative total. Before each `initWorker`, precheck the reader allocation of `max(2, ceil(used / 65536)) * 65536` bytes; afterward verify and charge the actual reader memory byte length via a public `copy: false` descriptor. Record every actual payload/reader byte length and their aggregate; a whole-Arena copy can include earlier fixture allocations, so logical entry counts never substitute for this byte guard. Reject an over-bound validator rather than dropping references, resetting an arena or relying on garbage collection. The writer Arena and all other process storage are covered separately by the process RSS guard.

Reads do not append arena bytes, so count feasibility is independent of the writer's arena-growth budget. The 2^24 cap bounds read work, not memory: a loop costing approximately 1.2 ns/read already reaches the 20 ms target at this ceiling; a still-faster loop is allowed to remain unresolved. Keep default arena limits unchanged; retain the 1 GiB process RSS ceiling, enforced by sampled RSS plus terminal high-water reporting (not a guarantee that every transient peak is observed), the 10-second child deadline and the 10-minute whole-screen deadline from first validation through final analysis. Exceeding a cap ends affected work as unresolved, without changing data/counts or buying more samples.

The exact child count is **400**: four untimed correctness-validation children (one per variant/engine, each checking all six fixtures), twelve baseline calibration children (one per case/engine, with pilots, warmup and verification in that same child), and 384 main-study children. There are no extra startup or verification launches.
