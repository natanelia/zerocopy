## 2. Keep the successful lifetime controls

Retain fresh processes, shared attached readers, unchanged public fixture operations, exact source/runtime/output pins, numeric preallocated records, two pretouches, synchronous lifecycle helpers and a pre-existing own-property holder. No iterator, yielded tuple or memory-API result object may escape into the suspended coordinator. Do not access private blocks to measure them.

For each memory cycle:

1. With fixture roots live and no iterator, perform the existing four event-loop-separated synchronous GC passes and sample **before**.
2. Create one iterator in a synchronous helper, advance once, validate/discard the result and retain only the iterator through the holder. Apply the same four passes and sample **paused**. E0's `done:true` is a completed empty-iterator control, not a successful suspension.
3. Resume the same iterator for validation where a second value exists; otherwise verify completion. Call `return()`, clear the holder, then apply the same four passes and sample **closed/released**. N=1 must verify completion rather than demand a nonexistent second pair.

Use Node's exposed synchronous GC and `Bun.gc(true)` exactly as in the accepted method. Preserve signed differences. Closed-minus-before is an attribution guard and a reported result; never subtract it from the paused increment. Recheck unique arena used bytes and capacities, unchanged at every state. No rebuilding, writes, buffer growth, cache clearing or result retention is permitted during measurement.

Keep P's two cycles, averaged into one process observation. Each additional small/boundary fixture gets **one predeclared cycle**, not an adaptive repeat. Proposed per-cycle attribution limits are 64 KiB for P; 512 bytes for N=0/1/32; 2 KiB for N=4096/4097/8192/8193. Apply these to Node T and its heap/external components, and Bun J and extra memory independently. Those tighter small-case limits are deliberately demanding: if natural drift exceeds them, small-memory attribution is unresolved, not evidence of zero regression. Net drift alone never proves absence of offsetting residue.

Retain one fresh no-library admission probe per engine, with the accepted four allocation kinds and lifecycle isolation. Add just one payload: **25 independently allocated Uint32Array(4096) blocks**, fully touched and retained without accessing `.buffer`, then released. This exercises the actual 16 KiB allocation class that the old 8 MiB typed-array probe could miss. Require its retained Node external and T increments, and Bun J increment, to cover at least 90% of the 409,600 requested bytes; preserve all component states and require release within 64 KiB in those admitting endpoints. This is a coarse accounting admission check, not proof of exact byte coverage. Preserve the original guards too. Stop on failure, without variants, additional diagnostic runs or replacement metrics. Later actual-cycle guards still apply.

## 3. Compact cases and why they are present

**Memory: eight sizes only:** 0, 1, 32, 4096, 4097, 8192, 8193 and P=100000. The first three check fixed/generator overhead, 4096 checks the last ordinary-array size, 4097 checks conversion plus nearly a block of slack, and 8192/8193 separate a full final block from the next allocation cliff. P tests material benefit at scale.

Build one additional stable numeric map through 8,193 writes, retaining only its roots at 1, 32, 4096, 4097, 8192 and 8193. These share one arena, kept static and counted once. Reuse E0 and P from the previous fixture recipe. This adds 8,193 public writes per child, rather than six separate builds. Freeze all roots before attachment and measurement; their shared arena does not turn snapshots into mutable live prefixes.

**Latency: retain the previous seven fixture recipes and their 14 endpoints per engine.** P covers large stable traversal; E0, F128 and F513 cover empty/small filtering; F100k covers large live filtering; D100k covers a long deleted prefix; O32k covers object decoding and ordinary GC/cache pressure. Preserve both engines and all these control roles, irrespective of the former candidate's results.

Add only:

- First-item-and-close aggregate cycles at 4096, 4097 and 8193: three controls cover the largest ordinary-array path, first conversion, and later block allocation without a full size-by-operation matrix. Keep 8192 for memory, but omit its separate timing control: 8193 includes scanning/reversing the preceding full blocks plus the next allocation, while P's full traversal covers sustained block traversal. The proposed claim does not require measuring a timing discontinuity by subtracting adjacent sizes. This removal follows mechanism coverage, not a historical result.
- P first-item-and-close aggregate cycle: one control charges the complete early-abandon lifecycle; the existing isolated first-next endpoint closes outside its timer.
- First public-module import in each fresh comparison child: one startup control charges the eager constructor-reference/module work. Time the actual import before fixtures, with the same public entrypoints as before. It has one observation per child, no within-process warmup or repeated cached import. Call it **fresh-process module-import latency**, not isolated binding cost, machine-cold import or complete application startup.

Thus there are **18 iteration latency endpoints plus one import endpoint per engine, 38 controls total**. Sizes 1/32 need memory/correctness checks, not another latency family. This is the smallest recommended reduction while preserving the previously distinct latency roles: the unchanged small filtering fixtures do not replace stable near-threshold scanning, isolated first-next excludes close cost, and warm iteration excludes eager module import. Correctness for malformed reads, borrowed receivers, callbacks and worker behavior remains a separate prerequisite, not a performance matrix.

Also record a startup memory contrast from four-GC before-import and after-import states, before fixtures. The import timer excludes those GCs. Compare the complete import footprint between arms, using T/J respectively; it includes module work and cannot isolate one reference. This closes the accounting gap left when the eager module binding is already present at every iterator's before state.

## 4. Finite schedule, uncertainty and decisions

Keep **eight adjacent baseline/candidate process pairs per engine**, alternating AB/BA and engine-first order. Use the accepted fixed case rotation and endpoint-order counterbalancing. No simultaneous subjects. Keep two baseline-only calibration children and the two admission probes: **36 scientific children total**, with no retries or follow-on diagnostic series.

After memory, retain the original two complete validation/cache-establishing traversals per latency fixture. For the 18 iteration endpoints, reuse the baseline-only fixed K ladder, target 20 ms, three verification chunks, four warmup chunks and six measured chunks; the process observation is the arithmetic mean of all six. Freeze K per engine/endpoint for both arms. Use the prior small-operation extended ladder only for aggregate lifecycle/empty endpoints. Preserve 0.5% clock-resolution/bracket-overhead rules, 5 ms calibration-verification floor and all valid slow/natural-GC chunks. The import endpoint uses the same 0.5% timer-resolution/overhead eligibility test on its single duration. No trimming, CV exclusion, outlier deletion, favorable subset, old calibration reuse, resampling or added pairs.

Proposed hard budget: two 20-second probes; two 120-second calibrations; 32 comparison children of 90 seconds; 120 seconds staging/pins, 90 seconds analysis/sealing and 60 seconds final cleanup. **Whole ceiling: 3,430 seconds (57 minutes 10 seconds).** Each comparison child allocates at most 5 seconds startup/import accounting, 20 setup, 30 memory, 25 warmup/timing, 5 final checks/output and 5 owned exit/cleanup. Calibration allocates 20 setup, 90 endpoint work and 10 output/exit seconds. These are nested maxima; all work and cleanup consume the whole ceiling.

The larger memory allowance pays for nine cycles rather than the former two, plus startup accounting. At the fixed 20 ms timing target, the 18 iteration endpoints expose only 3.6 seconds of nominal clocked work per child, 115.2 seconds across comparisons. Fixture work increases by about 3.6%. Actual GC/setup wall time is unestablished; these calculations justify a finite allowance, not a predicted completion time. Removing one timing endpoint leaves the same fixed ceilings and does not create permission for replacement work. Preserve the accepted 4 GiB effective-host admission, 2 GiB sampled group-RSS stop, 1 GiB post-fixture RSS admission, 512 MiB unique-arena limit and 50 ms external RSS sampling. A cap failure is incomplete evidence; do not enlarge the cap or shrink the case and retry.

Fix these **materiality choices before any packed-candidate data**:

- P: baseline retained-increment lower bound >512 KiB; baseline-minus-candidate saving lower bound >128 KiB; lower bound on `0.8×baseline − candidate` >0, establishing at least a 20% reduction in the mean retained increment. Use the paired arithmetic contrasts and simultaneous intervals below; do not divide a confidence endpoint by an estimated baseline or average individual fractional savings.
- Nonprimary memory: candidate-minus-baseline margin is **1 KiB** at 0/1/32 and **4 KiB** at 4096/4097/8192/8193. Startup import-footprint margin is **4 KiB**. These are explicit practical tolerances, not assertions of identical allocation.
- Latency: material regression remains **2%**. Use ordinary two-sided 95% paired Student-t intervals on the eight log ratios to detect harm; any valid lower bound >1.02 vetoes advancement of this unchanged candidate. Use 95% Bonferroni simultaneous upper bounds over all **38** latency controls for clearance, each at or below 1.02.
- Memory: paired arithmetic contrasts, with simultaneous 95% Bonferroni intervals over **22** contrasts: per engine, three P targets, seven nonprimary regressions and one import footprint. Any valid ordinary 95% lower bound above a nonprimary/startup memory margin is a material adverse control. Clearance requires its simultaneous upper bound at/below that margin. This harm-versus-clearance distinction deliberately makes stopping easier than claiming safety.

The 20% and 128 KiB targets define a substantial benefit prospectively for an O(N) representation that retains every pointer. A one-fifth reduction is meaningful relative to a measured large iterator; 128 KiB prevents a nominal percentage gain on a negligible byte difference and corresponds to more than 1.3 saved bytes per retained pointer at P. Requiring a confidently attributed baseline above 512 KiB keeps the benefit question well above small-object noise. These are practical decision thresholds, not physical predictions or statistical constants. The previous 50%/256 KiB targets belonged to a near-constant checkpoint-storage proposal and need not govern this mechanism. No candidate timings or memory samples exist to fit; the fixed block size and workloads are unchanged.

The independent unit is a process pair, n=8, df=7. This remains a small-sample, model-based screen. Preserve full distributions and predeclared leave-one-pair-out diagnostics, never use them to remove a valid adverse sample. Newly required Bonferroni critical values must be checked in the exact future packet; the old m=28/m=10 constants do not apply. No old scientific samples need to be opened for that mathematical check.

**A useful measured lead may justify a scoped draft PR without all-control clearance.** Require a valid material Node P benefit, no confidently material adverse control on either engine, no contradictory unexplained accounting shift, and the applicable correctness/integrity checks. The draft must lead with the measured engine, fixture and forced-GC retained-memory scope, prominently list every unresolved latency/memory/startup control and Bun coverage limitation, and avoid a general no-regression, total-RAM or all-platform claim. If Bun's bounded endpoint also meets the benefit targets, report that separate corroboration. A wide or measurement-limited interval is uncertainty, not a categorical bar to such a justified draft; it cannot be advertised as a passing control. Publication remains a separately authorized action.

**Strong scoped screen clearance** additionally requires both admitted memory scopes, all specified memory limits and all 38 latency controls to clear. It is a stronger result, not a prerequisite for every scoped draft. Valid confidently material adverse evidence always blocks promotion of this unchanged candidate, irrespective of its memory benefit. Identity, correctness, attribution or custody failures cannot be relabeled as merely noisy controls: invalid evidence supplies no positive support. Noisy unresolved controls in an otherwise complete valid run remain visible and do not erase independently valid benefit or harm.

## 5. Retention is not peak or RAM

At 4097, two blocks request 32,768 bytes with 16,380 bytes slack. At 8193, three request 49,152 with the same slack. At 100000, 25 request 409,600. These are payload arithmetic, excluding views, buffers, outer-array metadata and generator state.

The 4096-element ordinary prefix coexists with initial typed blocks during conversion. Clearing its reference does not collect it. Include one **fixed raw-pause diagnostic row** per cycle for P and the four boundary cases, immediately after the pause helper returns and before the existing GC barrier, in both arms. This adds no sample selection or GC passes and never replaces the post-GC endpoint. It may show uncollected residue; it cannot observe the highest allocation during the scan. External sampled RSS and process high-water RSS include setup and allocator history and can miss or obscure a brief conversion peak. No lower peak, lower process RAM, complete reclamation or engine-root-cause claim follows from this screen.

## Evidence and work boundary

The preceding accounting and lifetime assessments document an early Bun failure and a later limited lifetime correction: an earlier extra-memory release persisted into a later allocation interval, and even passing net-release guards did not establish complete per-kind reclamation. That history is why overlapping buckets and tight boundary attribution cannot be guessed away.

This prospective assessment used written methodological summaries, official documentation, file listing and SHA-256 hashing. It performed no library import, code execution, build, test, benchmark, installation, scientific-data reanalysis or resampling. Source validation, correctness and measurement are distinct evidence stages.
