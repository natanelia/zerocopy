# Copied session publication baseline — 26 November

Pinned main d57fc413ee5f67d0839f5a3a8ff36f4a51fb0341. No runtime changes. The prior adaptive reader lane was retired with [evidence](https://github.com/natanelia/zerocopy/commit/9bace7d5706005d4b15eb47682e54b756e7cd23f).

Hypothesis: copy-mode sessions allocate and copy the full used arena for each peer on every publication. The runtime uses a slice, ordinary structured clone, and a reader-side copy into WASM. The resulting overhead may dominate sparse edits at 100k objects and multiple readers. Copy mode is important for Bun's default and for explicitly isolated transport. Shared mode is a diagnostic contrast, not a semantically equivalent replacement for isolation. Previous descriptor construction (#61), registry attachment and read-cache proofs do not test this repeated copied session path with two real readers.

Unmodified public session API, two real Node workers, website catalog 1k/10k/100k, eight sequential 25-record sparse publications after initial connection, 100 ordinary reads in each worker per publication. Four alternating measured pairs per cohort/size, separate identical copy/copy AA pairs, one excluded warmup pair. Record synchronous publisher duration, complete time to both useful responses (includes verification and scheduling), reader query duration, bytes of copied payload and shared handles, and sampled memory separately. Verify every timed query, read-only writes, old snapshots, and all final and initial records per worker outside timings. Copy/shared isolation is deliberately not equated. No CPU/GC or peak process-memory claim from sampled heap or RSS. Raw artifacts retained. If a clear copy bottleneck is established, investigate avoiding an extra clone for truly native transferable endpoints without changing default copy isolation, custom endpoint contracts, or old reader snapshots; separately prove portability. Do not modify runtime before inspecting baseline. Do not merge proof or publish Pages.

Do not count the shared contrast as an achieved optimization.

Next candidate: explicit per-connection `transferCopies: true` in copy mode, leaving default behavior unchanged. The publisher already slices a fresh independent used-arena buffer per peer; transfer that buffer to a compatible endpoint instead of cloning it again. Do not transfer the owner's backing memory or share a copy between peers. The reader still copies into isolated WASM; this is not incremental/delta transport or a zero-copy wire format. This additive option requires an endpoint supporting a native transfer list and is experimental. The proof verifies per-peer actual detachment, one-argument default sends, exact owner/reader old and new values, and read-only behavior. AB compares pinned baseline copy to candidate opt-in; AA identical baseline copies; default and shared arms compare pinned baseline and candidate unchanged modes. Four alternating measured pairs per size/cohort, eight successive sparse publications per session. Existing test suite and typecheck run on candidate; browser/Bun and richer queue/error/alias/multi-arena tests would follow only if the screen establishes useful end-to-end gains without default regressions.
