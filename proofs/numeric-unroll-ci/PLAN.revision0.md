## 5. First-use cost: intentionally unresolved in this first screen

The +92 bytes can affect base64 decode, Wasm decode/compile, code layout and first instance cost. `numeric.ts` compiles lazily on the first valid numeric or spatial call and caches the Module; subsequent new Arenas instantiate from that already compiled Module. Ordinary entry files remain identical, but that footprint fact is not a measured zero-cost startup result. A spatial-only consumer can pay the changed SIMD module's first-use cost even though its called body is identical. Forced-scalar consumers still parse the changed portable JS entry containing both binaries.

This screen warms both closures and each measured Arena instance. It measures none of those startup regions. Repeated calls, new Arenas, fixed-query module aliases, or repeated `new WebAssembly.Instance` from a cached Module must not be labeled first-use compilation. The warm spatial and scalar controls do not clear first-use risk. Keep **first import / first range / first spatial-only use unresolved** in every result summary.

This deliberate omission makes the initial experiment proportionate and is a hard barrier to promotion, not an assumption of negligible cost. Only if the warm lead survives should a separate small first-use protocol be considered. It must use fresh processes for each source observation, with no prior numeric import/call/module construction, and distinct first-range and first-spatial-only process groups. At minimum, time official numeric import separately from the first valid call on a prebuilt list; the latter includes probe, base64 decode, actual Module creation, instance creation and that call. Retain the combined first-use interval too. Ordinary-entry-only fresh-process control can distinguish unrelated launch/import effects. Treat OS file-cache state and engine compilation strategy honestly; do not claim cold disk or fully isolated compiler time without evidence. If single-call noise/resolution defeats useful inference, keep first-use unresolved rather than increasing repetitions within one process. This later protocol, sample count, caps and thresholds require separate review before clocks.
