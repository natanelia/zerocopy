## Source, arithmetic, and memory review

The entire runtime delta is the eight-line addition in `numeric-kernels.as.ts:8–22`. For a span of `count <= 32`, `i` starts at zero. Each quartet iteration is entered only when `count - i >= 4`; its loads cover values `i..i+1` and `i+2..i+3`. Advancing by four preserves `i <= count`, so unsigned subtraction cannot wrap. The original pair loop consumes at most one remaining pair; the original scalar loop consumes at most one remaining value. No new memory operation reaches bytes beyond the visible span, even where accessible memory after an odd snapshot belongs to a writer. The second emitted load uses `offset=16` from the already computed first address, which is equivalent for these bounded valid spans.

The public kernel entry and tree traversal are unchanged. `treeSize = (size - 1) & ~31` leaves a tail of 1–32 values for nonempty snapshots; valid tree leaves contribute at most 32. Empty input, NaN bounds, and reversed bounds return before any data load. Public type checks remain in `numeric.ts:33–37`, and the wrapper returns before kernel initialization for those empty/invalid intervals.

Both vector loads use `f64x2.ge(values, lower)` AND `f64x2.le(values, upper)`. NaNs never satisfy both ordered comparisons; infinities, finite extrema, subnormals, inclusive endpoints, and ±0 retain the same comparison rules. The scalar WAT expresses the upper comparison as `hi >= value`, equivalent to `value <= hi` including NaNs. There is no floating-point reduction or reassociation: a true vector predicate is an all-ones integer mask, and subtracting it increments that lane by one. Each combined SIMD lane contains at most 16; each leaf at most 32; disjoint-subtree totals remain at most public `MAX_SIZE = 0x3fffffff`. Narrowing lane counts to u32 and returning the existing i32 ABI is exact within those bounds. Maximum-size lists were not allocated by the corpus, and source reasoning is necessary for that bound.

The optimized WAT reuses accumulator locals as load temporaries with `local.tee`. This is correct: the old accumulator operand is evaluated and placed on the Wasm stack before evaluating the mask operand, whose load overwrites the local; the final `local.set` stores the subtraction result. The added vector local is implicitly initialized to zero. No explicit zero-vector instruction is emitted. This does not establish how native registers or machine instructions are allocated.

All added state is invocation-local. There are no stores, allocator calls, mutable module state, shared scratch bytes, output buffers, changes to storage format, or changes to tree traversal. Scalar numeric is byte-identical. Spatial bodies and public loader behavior are unchanged, although a larger shared numeric module can affect first-use or code-layout cost for spatial-only users.

For 32 values, independent examination confirms vector backedges 16→8, loop guards including exits and remainder guard 17→10, and address shift/add computations 16→8. Both versions still execute 16 vector loads, 32 f64-vector comparisons, and 16 integer-vector subtractions; the candidate adds one vector combine. For sizes 1–3, the quartet loop does no work and adds a failed guard plus a combine. At size 4 the total vector guard count is unchanged. No speed claim follows from these counts.

## Corpus and worker evidence

The corrected corpus is a fixed 173-line file. Its independent JS oracle implements inclusive ordered comparisons. The suite covers every size 0–32, every quartet remainder, actual memory ends, accessible matching poison, all-hit/all-miss/alternating data, and every exceptional value at every position of a full 32-value span. The 256 xorshift cases per process and fixed endpoint cases are deterministic. Invalid-bound and empty calls use invalid pointers to demonstrate the early return. Exact memory digests surround every direct fixture. NaN payload encodings are not exhaustively enumerated; the unchanged ordered operations provide the semantic argument for all NaNs.

Public cases cover the stated small sizes, tail/tree boundaries through 32,801 values, snapshots, set/pop/fork/growth, errors, and unchanged spatial counting. Shared and copied attachments verify exact counts, read-only rejection, memory-digest preservation, and unchanged attached arena-used values. Normal and forced-scalar public selection run in separate processes; direct scalar and SIMD modules are exercised in every process. Accordingly, the eight-process assertion totals include repeated fixed inputs and are not claims of that many unique cases.

The corrected worker proof checks two workers per process, shared then copied. The old 33-value snapshot's last visible tail remains one element while the owner appends matching values, demonstrably grows its memory, and edits a fork. Each worker reads before, during the scheduled owner operation, and afterward, checks each count, rejects writes, and reports one module-selection probe. Awaited `worker.terminate()` is in `finally`. The copied reader is independent of subsequent owner growth; the shared reader exercises the shared transport. Scheduling overlap is established at task level only, not overlap of a particular load with `memory.grow`.

The first custom process failed with `ERR_INVALID_ARG_TYPE` at its listener-removal line. Its parameter named `error` shadowed the surrounding error callback, so a successful response passed null to `worker.off`. A direct text comparison proves that v2 only renames this parameter to `reason` and changes reject/resolve dispatch to use it; timer, listener-removal target, inputs, assertions, worker count/work, and runtime variants remain identical. The original process is correctly excluded from passing results.

## Retained timeouts: what they do and do not establish

The existing Vitest configuration has `testTimeout: 5000`, thread pool, file parallelism enabled, and 1–4 workers. Those inputs and the exact commands are preserved.

- Baseline spatial attachment/snapshot/growth test: timeout, 8,699 ms reported for the test.
- Candidate same spatial test: timeout, 10,343 ms reported.
- Candidate numeric attachment/byte-comparison test: timeout, 6,380 ms reported.

These are existing runner-reported durations, not measurements collected by this review. No value-mismatch exception is reported; that does not prove every assertion completed before the timeout. The mapped stack locations do not identify the operation taking the time.

The numeric test performs one five-value range call after attachment, then deep equality of the complete backing Uint8Array (the default initial memory is 131,072 bytes), and finally write rejection. The spatial test builds a 34-value original, attaches it, appends 32,768 values, edits the fork, checks old/attached/changed values, then deep-compares the whole grown buffer. `initWorker` includes arena instantiation and snapshot reconstruction. Each of these is part of the test boundary. Deep equality is a concrete diagnostic candidate, but no retained record localizes time to it. The candidate's scan does add bounded tail work; the evidence neither attributes seconds to that work nor eliminates a regression. Spatial source identity likewise cannot prove unchanged first-use or module-layout timing.

Do not call these failures harmless scheduling noise, a proven byte-comparison bottleneck, or a performance regression from this record. Keep both original suite outcomes and the candidate-only timeout unresolved. The next diagnostic and eventual clean gate must retain this distinction.
