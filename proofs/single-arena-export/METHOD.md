## Sampling and fixed bounds

There are **six blocks per engine**, each with fresh independent baseline B, candidate C, and baseline A processes: **36 measurement children** total. A imports the exact same baseline artifact as B, in a separate process. Use these six within-block orders, once each and fixed now: `B C A`, `A B C`, `C A B`, `B A C`, `C B A`, `A C B`. Alternate which engine runs first across blocks (Node first in odd blocks). Run children sequentially on the same hosted machine without concurrent build/test/benchmark work; record hardware, OS, host/job identity, runtime versions, relevant flags and process timestamps. Do not choose order after seeing results.

One extra baseline-only calibration child per engine selects operation counts, so at most **38 study children**. For each case start with 256 operations (T: 64). At a trial count run five warm-up batches and three pilot batches; use the pilot median only to select counts. Aim for 30 ms, accepting 20–50 ms. Otherwise scale the count by `30 ms / pilot median`, rounded to a positive integer and clipped to its cap. Allow at most four trials, without inspecting candidate timing. Caps: 2^20 operations/batch; R may use 2^24; T also has a cap of 4096 calls and 512 MiB copied per batch. If no accepted count is found, uncalibrated S blocks the screen; any other row retains its last attempted count and is measured but remains unresolved, with all adverse evidence retained. Do not skip rows or tune further. Freeze all counts before measurement. Calibration data are retained but excluded from estimates.

Every measurement child constructs S first. Before any other `getWorkerData` call, time exactly one S export and validate it afterward. Record this first-export observation separately. Also record parent spawn-to-ready time (ready means imported entry plus constructed S), explicitly including scheduling and readiness-message overhead; this is a descriptive startup observation, not API or worker-transfer latency. These sparse cold observations carry no warmed performance verdict.

Then finish fixture setup. In table order, each case receives **five discarded warm-up batches and nine measured batches**, all at its frozen count. Use a high-resolution monotonic timer around the operation loop only. Consume every result through a fixed minimal checksum (export arena-array length; R's numeric value), emit/check that checksum after the batch, and keep at most the latest result. Full validation stays outside timing. The estimand includes this identical loop/checksum cost; do not subtract an empty-loop estimate. No explicit GC, outlier deletion, batch trimming, selective repeats or optional stopping. Retain every elapsed duration, count, checksum and validation outcome.

A case's process observation is the arithmetic mean of its nine elapsed-per-operation values. Mark a case quality-unresolved if a process has a nonpositive/nonfinite duration, any measured batch below 10 ms, within-process batch CV above 25%, or a last-three/first-three batch-mean ratio outside 0.85–1.15. Keep flagged data visible; never repair a result by dropping it. Any S quality failure blocks a gain verdict; control quality failures stay explicit. Wrong output, missing process, timeout, crash or resource termination stops the complete screen as incomplete.

The entire performance study, including calibration, fixture setup, launches, collection, analysis and cleanup, has a **14 min 30 s hard wall cap**, with **90 s per child** and no replacement children. The supervisor samples summed process-group RSS every **50 ms** and terminates the group at **2 GiB**. This is a sampled safety ceiling with possible overshoot and shared-page double counting, not a strict physical-memory cap, memory outcome or accounting calibration. Keep the same sampler for all children; its scheduling cost remains a hosted-screen limitation. Do not impose a virtual-address-space limit or reconfigure the runner. On a cap or interruption, terminate/reap descendants and preserve partial logs. Remove only study-created disposable fixtures/build copies after recording their digests; preserve all evidence.

## Analysis and prospective decision

For each case/engine/block form `d = log(C/B)` from the process observations. With the six block values, report geometric ratio `exp(mean(d))` and the **two-sided paired 95% Student-t interval**, `exp(mean(d) ± 2.570582 × sd(d)/sqrt(6))`. Batches are not independent replicates. No bootstrap, resampling, pooling engines, choice between baselines, or replacement of B by a favorable baseline average. These small-n intervals assume approximately independent, reasonably behaved block log-ratios; balance and diagnostics do not prove that assumption on a shared host.

For A/A diagnostics report the same intervals for `log(A/B)` and, separately, `log(later baseline / earlier baseline)` within each block, plus the chronological observations. A diagnostic is major systematic bias only when its entire interval is above 1.05 or below 0.95. An isolated noisy point or an interval merely crossing 1 is not a regression. Major S or R A/A bias blocks the hosted gain verdict; other biased controls are unresolved. Report all diagnostics, including large scatter that leaves an inconclusive interval.

A meaningful primary lead requires S's ratio **≤0.95 and 95% upper bound ≤0.95 in both engines**, with complete source/correctness/quality admission. Every other warmed row is a control: **no control may have a 95% lower bound >1.02** in either engine. Such a result parks the candidate. A control whose upper bound exceeds 1.02 without a lower bound above 1.02 is explicitly unresolved, not passed; unresolved controls do not trigger more samples. Cold/startup observations remain unresolved diagnostics, not a passed no-harm control or an exemption: any apparent material adverse cold result requires review before promotion. The joint two-engine primary requirement is a conjunction, not a search for the best endpoint; unadjusted control intervals are conservative screen warnings, not simultaneous no-regression certification.

Report absolute ns/op, all six process means and paired ratios, intervals, calibration/quality/A-A results, cold observations and exact limitations. A passing outcome is only “promising hosted export-latency lead, with [named] unresolved controls,” never full no-regression or portability clearance. Failure to meet the 5% criterion ends this screen without seeking tighter bounds. Preserve exact commands/working directories, environment and source/runtime pins, stdout/stderr/exit statuses, all raw JSON, manifest and analysis inputs/output.
